TrainingArguments常用参数整理

使用相关
output_dir 输出文件夹
num_train_epochs 微调轮次
logging_steps 每隔几个step log一次

保存相关
save_strategy no/step/epoch 保存策略
save_steps 每隔多少个step保存一次
save_total_limit 最多保留多少个检查点
load_best_model_at_end 是否保存最优模型

优化算法相关
optim：选择什么优化器 比如adamw
优化器下对应的参数
learning_rate 学习率
weight_decay 权重衰减 相当于 加上L2正则化，会限制模型的权重都会趋近于0 防止过拟合
warmup_ratio 学习率预热 训练一开始从0逐渐增大到lr 设置为0.1则在10%的样本上执行学习率预热
warmup_steps 另一种设置学习率预热的方式
lr_scheduler_type 学习率调整器 设定学习率变化的方式，主要包括 "linear"-线性变化 "cosine"-余弦退火 "constant"-恒定


其他
精度选择 比如bf16
per_device_train_batch_size 每个设备上批大小
gradient_accumulation_steps 梯度累积，相当于增大batch size
Gradient Checkpointing 是否设置梯度检查点 进一步节省内存(不保存整个计算图的所有中间结果, 而是在反向传播的过程中重新计算)
seed 随机数种子 用于复现


验证相关
do_eval 是否eval
evaluation_strategy no/step/epoch 决定什么时间eval
eval_steps 几个step后eval
metric_for_best_model 最优的评判指标，默认是loss
greater_is_better 该指标是否是越大越好

自定义评价指标和loss

compute_loss_func(outputs, labels, num_items_in_batch=num_items_in_batch) 自定义loss 默认是标签平滑损失
compute_metrics 自定义评价指标 接受的是一个EvalPrediction对象，包含predictions(logits) label_ids 和 inputs
使用示例：https://www.guyuehome.com/detail?id=1942200070747258882

batch相关

普通训练：
1. micro_batch_size（微批次大小）
定义：每张 GPU 在一次前向/反向传播中实际处理的样本数量。
特点：
这是最小的计算单元。
受限于单张 GPU 的显存容量——如果 micro_batch_size 太大，会爆显存。
也称为 per-device batch size 或 local batch size per forward pass。
举例：如果你有 1 张 GPU，micro_batch_size = 4，那么每次前向传播就用 4 个样本。

2. gradient_accumulation_steps（梯度累积步数）
作用：当显存不足以支撑较大的 batch 时，可以通过多次小 batch 前向/反向计算，累积梯度，最后再统一更新参数。
效果：等效于使用更大的 batch，但分多次计算。
注意：梯度累积是在同一张卡上进行的（不跨设备）。
举例：micro_batch_size = 4，gradient_accumulation_steps = 3
→ 实际每张卡在一次参数更新前，会处理 4 \times 3 = 12 个样本，并累积这 3 次的梯度。

3. mini_batch_size（小批次大小）
定义：每张 GPU 在一次完整的参数更新周期内处理的总样本数。
公式：

$\text{minibatchsize} = \text{gradientaccumulationsteps} \times \text{microbatchsize}$
接上例：mini_batch_size = 3 × 4 = 12

4. DP（Data Parallelism，数据并行）
表示你用了多少张 GPU 来做数据并行训练。
每张 GPU 拿不同的数据子集，但模型结构相同。
训练时，各卡独立计算梯度，然后通过 All-Reduce 同步梯度，再统一更新模型。
举例：DP = 8，表示用了 8 张 GPU 做数据并行。
5. global_batch_size（全局批次大小）
定义：整个训练系统（所有 GPU）在一次参数更新中总共使用的样本数。
公式：

$\text{globalbatchsize} = \text{DP} \times \text{minibatchsize}$

而因为 mini_batch_size = gradient_accumulation_steps × micro_batch_size，所以也可以写成：

$\text{globalbatchsize} = \text{DP} \times \text{gradientaccumulationsteps} \times \text{microbatchsize}$
举例：
DP = 8（8 张 GPU）
gradient_accumulation_steps = 3
micro_batch_size = 4
→ global_batch_size = 8 × 3 × 4 = 96
这意味着：每完成一次模型参数更新，整个系统共“看过”了 96 个样本。
